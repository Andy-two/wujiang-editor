# 主将 / 副将 / 羁绊 机制对比

> 数据源：`data/editor/generals.json`（56 主将）、`data/vice_generals.json`（109 副将）、`data/editor/talents.json`（35 天赋）
> 代码：`scripts/core/ed_data.gd`、`scripts/core/ed_battle.gd`、`scripts/ui/editor.gd`

## 一、一句话结论

| 概念 | 数据 | 引擎 | 编辑器 UI |
|---|---|---|---|
| **主将** | 56 个，完整 | ✅ 完整实装 | ✅ 完整 |

## 二、主将 vs 副将 结构对比

### 字段差异

| 主将独有（21 个字段） | 副将独有（7 个字段） | 共有（4 个） |

```

```

ID 不重叠，但都落在 1xxx / 2xxx / 3xxx 段，**没有明确区分位**——靠文件区分。

## 三、副将的三个组成部分

每个副将 = **1 个固定天赋 + 0~2 条韬略 + 属性加成**

```json
{
  "id": 1201,
  "name": "鲍信",
  "quality": 1,  "quality_name": "超",
  "effect_name": "御锋",                              // ← ① 固定天赋
  "effect_desc": "每回合受到的首次伤害降低15%。",
  "taolue": ["提升1.5%兵力", "战斗中伤害提升2%"],      // ← ② 韬略
  "stats": {"hp": 1.5},                                // ← ③ 属性加成
  "dmg": 2                                             // ← ③ 伤害加成%
}
```

### ① 固定天赋效果（核心机制）

- **103 个不同效果名**（109 个副将中只有 2 组重名）
- 重名情况：`×6`（颜良、文丑、王允、陈宫、徐庶、张昭）、`富瞻 ×2`（王朗、孙资）
- 效果类型覆盖：增伤/减伤、暴击、追击、反击、护盾、治疗、控制、资源层数……
- **复杂度与主将天赋同级别**，但都绑定在"装备这个副将的主将身上"

### ② 韬略（纯数值）

- **22 条不同文案**，81 个副将有 2 条，28 个副将没有
- 全部是纯数值加成，形如「提升1.5%物攻」「战斗中伤害提升2%」
- 高频：`提升1.5%物攻`×26、`战斗中受到伤害减免2%`×23、`提升1.5%谋攻`×19

### ③ 属性加成

- `stats`：`hp`(26) / `atk`(44) / `def`(17) / `matk`(42) / `mdef`(9) 的百分比
- `dmg`：0~30 的伤害加成，45 个副将为 0

### 品质分布

| 品质 | quality | 数量 |
|---|---|---|
| 奇 | 0 | 6 |
| 超 | 1 | 80 |
| 杰 | 2 | 23 |

## 四、关于「羁绊」—— 三个层面逐一核查

### 层面 1：副将之间有没有羁绊？→ **没有**

| 检查项 | 结果 |
|---|---|
| 数据结构里有组合字段（pair/group/set）吗 | ❌ 没有 |
| 效果文案里点名其他武将吗 | ❌ **0 / 109** |
| 文案里有「同场/同时/阵容/上阵/组合/搭配」等词吗 | ❌ **0 / 109** |
| 副将是否限定只能配某人 | ❌ 没有 `owner_id`/`exclusive` |

**所有 109 个副将效果都是独立作用于主将自身，互相之间零关联。**

### 层面 2：主将之间有没有羁绊？→ **有，是"天赋共享"，但实现有缺陷**

`talents.json` 只有 35 个天赋，56 个主将**共用**：

| 共享天赋 | 使用者 |
|---|---|
| `xy_talent` 机鉴先识 | 荀彧、荀攸、陈群、糜竺、李典（5人） |
| `biyue_xiuhua` 闭月羞花 | 貂蝉、小乔、大乔、甘梅（4人） |
| `cr_talent` 贲育弗加 | 曹仁、高顺、曹洪（3人） |
| `sm_talent` 鹰视狼顾 | 司马懿、贾诩、陈登（3人） |
| `gj_talent` 经天纬地 | 郭嘉、周瑜、刘晔（3人） |
| `xhd_talent` 刚烈无惧 | 夏侯惇、张绣、陈到（3人） |
| `ma_chao_talent` 神威天将 | 马超、庞德、纪灵（3人） |
| `sun_talent` 枭姬 | 孙尚香、孙权、简雍（3人） |

### ⚠️ 但这里有个真实的数据缺陷

**23 个武将有专属的天赋名和描述，引擎却不读它们。**

```json
"zhou_yu": {
  "talent": "gj_talent",                    // ← 引擎读这个：经天纬地（郭嘉的）
  "talent_name": "雄姿英发",                 // ← 引擎不读：周瑜真正的天赋
  "talent_desc": "根据自身谋防的40%提升周围3格范围..."
}
```

`_apply_talent_effects()` 只读 `talents.json[talent]`，**完全忽略 `talent_name` / `talent_desc` / `talent_stages`**。

**后果：23 个武将在战斗里用的是别人的天赋效果。**

典型误配：

| 武将 | 实际挂的天赋 | 应该是 |
|---|---|---|
| 周瑜 | 经天纬地（郭嘉的） | 雄姿英发 |
| 典韦 | 樊哙在世（许褚的） | 万夫不当 |
| 孙权 | 枭姬（孙尚香的） | 坐断东南 |
| 吕玲绮 | 武圣（关羽的） | 将门虎女 |
| 简雍 | 枭姬（孙尚香的） | 巧舌 |
| 庞德 | 神威天将（马超的） | 白马壮节 |
| 贾诩 | 鹰视狼顾（司马懿的） | 毒士 |
| 大乔/小乔/甘梅 | 闭月羞花（貂蝉的） | 国色/国色/贤内助 |

**其余 33 个武将**（吕布、关羽、张飞、赵云、诸葛亮…）没有专属天赋，挂的就是共享天赋，这个是正确的。

### 层面 3：副将 → 主将 的关系

主将侧预留了字段：

```gdscript
"vice_id": 0,      // 副将 ID
"vice_dmg": 0.0,   // 副将伤害浮动
```

**56 个主将全部为 0** —— 字段预留但从未填写。且 `vice_id` 是**单值**，意味着设计上「1 主将 : 1 副将」，不是「1 : 多」。

## 六、这解释了之前"35 vs 56"的疑问

我上一轮说"天赋是共享的，所以 35 < 56 是正常的"——**这个结论对了一半，但漏掉了关键事实**：

```
56 个主将
├── 23 个有专属天赋名（talent_name）但引擎不读 → 实际用着别人的天赋
└── 33 个确实共用 talents.json 里的 34 个天赋 → 这部分是设计意图
```

所以：
- **数据层面**：`talents.json` 的 35 条是"基础天赋库"，专属天赋写在 `generals.json` 的 `talent_name` 里，**两套并存**
- **引擎层面**：只认前者，后者被忽略

## 七、如果要补齐，工作量评估

### A. 副将系统（全新）

| 子任务 | 说明 |
|---|---|
| 数据接入 | 主将 `vice_id` 单值 → 需要先定义"装备副将"的规则 |
| 属性加成 | `stats` + `dmg` + `taolue` 应用到主将面板，**这部分是纯数值，最简单** |
| 固定天赋 | 109 个 `effect_desc` → 需要转成 `ed_fx_list` 效果块，机制复杂度等同主将天赋 |
| 编辑器 UI | 副将列表、装备、预览，从零做 |

**分两层：**
- **数值层**（stats/dmg/taolue）：简单，1 个阶段能做完
- **机制层**（109 个 effect_desc）：复杂，等同再做一遍天赋实装

### B. 主将专属天赋接入

- 让 `_apply_talent_effects()` 优先读 `talent_name`/`talent_desc`
- 但 `talent_desc` 是纯文本，需要补 `ed_fx_list` → 同一个问题

### C. 羁绊

**数据里根本没有这个概念，做不了。** 除非你来定义规则（谁和谁羁绊、触发什么效果）。

## 八、建议优先级

1. **先修主将天赋误配**（33 个用着别人天赋的问题）—— 但这需要补 `talent_desc` 的效果块，属于大工程
2. **副将数值层先行** —— `stats`/`dmg`/`taolue` 是纯数值，可以快速让副将"有作用"
3. **副将机制层** —— 109 个 effect_desc 转效果块
4. **羁绊** —— 需要你先定义规则
